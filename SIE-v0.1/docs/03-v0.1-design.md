# SIE V0.1 — Initial System Design

## Core Loop

```text
USER GOAL
   ↓
GOAL INTERPRETER
   ↓
DESIRED OUTCOME
   ↓
STRUCTURE GENERATOR
   ↓
INITIAL EXECUTION STRUCTURE
   ↓
NEXT-ACTION SELECTOR
   ↓
ONE ACTION PRESENTED TO USER
```

## Design Philosophy

SIE should reason about the path internally while minimizing what the user must simultaneously remember, organize, prioritize, and act upon.

The system is not intended to be a conventional to-do list. The user supplies an intention; SIE helps construct the structure between that intention and execution.

## V0.1 Components

### 1. Goal Input
Receives the user's natural-language goal.

### 2. Goal Interpreter
Determines:

- What outcome is desired?
- Is the outcome sufficiently defined?
- What essential information is missing?

### 3. Structure Generator
Creates an initial structure appropriate to the goal.

Different goals may require different structures. An academic goal, engineering build, business launch, and creative project should not automatically receive the same template.

### 4. Next-Action Selector
Determines the first useful action that should be surfaced to the user.

For V0.1 this logic can remain relatively simple. More advanced prioritization, constraints, dependencies, and adaptive restructuring belong to later experiments.

### 5. User Interface
The primary interface should emphasize:

- The active goal.
- One next action.
- A way to continue interacting with SIE.

Detailed structure can be available when useful but should not dominate the default experience.

## Future Concepts — Not V0.1 Requirements

The following concepts have been identified but are intentionally parked:

- PREP vs WORK classification.
- Purpose-aware actions.
- Adaptive restructuring when circumstances change.
- Project state and evidence.
- Dependency and critical-path reasoning.
- Calendar and availability awareness.
- External integrations.
- Idea Inbox and active-project limits.
- Execution metrics and experimentation.
- Mechanical-engineering validation project.

They should be introduced progressively only when testing demonstrates a need for them.
